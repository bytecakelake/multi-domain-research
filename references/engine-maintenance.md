# Engine Maintenance Procedure (changing rlab code)

This is the procedure for fixing the engine, gates, CLI, and selftest. When changing only documentation, just use `skill_manage` patch on the relevant file. The skill folder is the original, but code changes are first verified and merged via PR in the public repository and then moved into the skill (for documentation changes it is the reverse: from the skill to the repository with `tools/sync_from_skill.py`).

## Procedure

1. **Start from evidence.** Confirm a defect with figures from real run ledgers and logs, and for each item write acceptance criteria verifiable by evidence, change, and regression test. If there is no user score, do not claim quality improvement; only state reduced defects and rework.
2. **One concern = one PR.** Items touching the same function (`next_actions`, `retry_task`, etc.) proceed serially. The order is merge → `git pull` → next branch; delegate in parallel only when files do not overlap.
3. **Delegate with the design written as a contract.** Write state names, commands, and non-goals into the goal verbatim, and state explicitly that schema (DDL) changes are forbidden (if needed use `events` and `meta`, and `tasks.status` is free text) and that the child must not commit/push. The parent creates the branch first. Have tests written starting from reproducing the problem created by the previous behavior (RED first).
4. **Parent verification (do not trust the child's report).** ① Read the entire diff. ② In a temporary copy, revert only the implementation files and confirm that the new tests actually fail. ③ Run the full selftest yourself (background recommended). ④ Run the real CLI once on a synthetic run (argument collisions, reject paths, single/batch modes). ⑤ Deliberately weaken the new safeguards (rollback, caps, auto-halt) and confirm by mutation that the tests fail; if you could not, note it as a limitation.
5. **State/classification changes audit dependent features.** When you add a state or change its meaning, grep for all of that state literal and the timestamp predicates that rely on it (`dispatched IS NOT NULL`, etc.), and test in that exact realistic flow (emitted → failed → retried) whether the auto-halt group, the concurrency cap, and the gates still fire. Columns that fixtures fill in by hand hide gaps in this flow. A classifier that triggers auto-halt makes a false positive a halt, so keep it narrow: no bare numbers or generic words, only codes with context such as HTTP/status/error, and judge ingestion-result phrases (proof/rejected) before environment phrases.
6. **When a fix breaks a child's test,** read what that assertion expects and judge. If the expectation itself froze a defect as normal, rewrite it with the rationale and state it in the PR body. Do not just fix the test without judgment.
7. **Repository files are CRLF.** Do byte-level edits with Python, and check that all added/removed lines in `git diff -U0` end with `\r` (an empty string satisfies `'' in '+-'`, so filter with `l and l[0] in '+-'`). Require the same check from children.
8. **Report before merging.** If there is no CI, state in the PR body that the local selftest is the only verification. After a squash merge, confirm `state,mergedAt` and that the local default branch = `origin`. Defects found and fixed in review are listed separately in the PR body.
9. **Reflect it in the skill.** A `skill_manage` patch batch is atomic (if an anchor matches more than one place, the whole batch is rolled back, so use a unique line as the anchor). For each file, compare against the repository HEAD with `sha256`, and if they differ, find the location with `diff` (even a single blank line is caught). `SKILL.md` is continually edited by the curator, so do not overwrite it wholesale; edit it line by line, and fix in place existing sentences that conflict with the new behavior (e.g. "not yet implemented", superseded workarounds). After reflecting, run the selftest directly in the skill folder (`PYTHONDONTWRITEBYTECODE=1`, a temporary `RLAB_HOME`) and confirm with `sync_from_skill.py` that the mirror matches.
10. **When checking effects against existing run ledgers,** query only a read-only copy and delete it afterward (`references/data-lab.md`). If the provenance notation of past rows has been overwritten, classify conservatively per claim and write the definition together.
