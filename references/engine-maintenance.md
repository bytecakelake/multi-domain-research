# 엔진 유지보수 절차 (rlab 코드 변경)

엔진·게이트·CLI·selftest를 고칠 때의 절차입니다. 문서만 고칠 때는 해당 파일에 `skill_manage` patch만 쓰면 됩니다. 스킬 폴더가 원본이지만 코드 변경은 공개 저장소에서 PR로 먼저 검증하고 병합한 뒤 스킬에 옮깁니다(문서 변경은 반대로 스킬에서 저장소로 `tools/sync_from_skill.py`).

## 절차

1. **증거에서 시작합니다.** 결함은 실제 run 원장·로그의 수치로 확인하고, 항목마다 증거·변경·회귀 테스트로 검증 가능한 합격 기준을 적습니다. 사용자 점수가 없으면 품질 향상은 주장하지 말고 결함·재작업 감소만 말합니다.
2. **한 관심사 = 한 PR.** 같은 함수(`next_actions`, `retry_task` 등)를 건드리는 항목은 직렬로 진행합니다. 병합 → `git pull` → 다음 브랜치 순서이며, 병렬 위임은 파일이 겹치지 않을 때만 합니다.
3. **설계를 계약으로 적어 위임합니다.** 상태 이름·명령·비목표를 goal에 그대로 쓰고, 스키마(DDL) 변경 금지(필요하면 `events`·`meta`를 쓰고 `tasks.status`는 자유 텍스트)와 자식의 commit/push 금지를 명시합니다. 부모가 브랜치를 먼저 만듭니다. 테스트는 이전 동작이 만든 문제를 재현하는 것부터 쓰게(RED 먼저) 합니다.
4. **부모 검증(자식 보고를 믿지 않습니다).** ① diff 전체를 읽습니다. ② 임시 사본에서 구현 파일만 되돌려 새 테스트가 실제로 실패하는지 확인합니다. ③ 전체 selftest를 직접 돌립니다(백그라운드 권장). ④ 합성 run에 실제 CLI를 한 번 돌립니다(인자 충돌·거부 경로·단일/일괄 모드). ⑤ 새 안전장치(롤백·상한·자동 중단)를 일부러 약화해 테스트가 실패하는지 변이로 확인하고, 못 했으면 한계로 적습니다.
5. **상태·분류 변경은 의존 기능을 감사합니다.** 상태를 추가하거나 뜻을 바꾸면 그 상태 리터럴과 이에 기대는 타임스탬프 술어(`dispatched IS NOT NULL` 등)를 전부 grep하고, 자동 중단 그룹·동시 수 상한·게이트가 현실 흐름(내보냄 → 실패 → 재시도)에서 여전히 발동하는지 그 흐름 그대로 시험합니다. 픽스처가 손으로 채운 컬럼은 이 흐름의 틈을 가립니다. 자동 중단을 일으키는 분류기는 오탐이 곧 중단이므로 좁게 만듭니다: 맨 숫자·일반 단어 금지, HTTP/status/error 같은 문맥이 있는 코드만, 수집 결과 문구(proof/rejected)를 환경 문구보다 먼저 판정합니다.
6. **수정이 자식의 테스트를 깨면** 그 단언이 무엇을 기대하는지 읽고 판단합니다. 기대 자체가 결함을 정상으로 고정한 것이면 근거와 함께 다시 쓰고 PR 본문에 밝힙니다. 판단 없이 테스트만 고치지 않습니다.
7. **저장소 파일은 CRLF입니다.** 파이썬으로 바이트 단위 편집을 하고, `git diff -U0`의 추가·삭제 줄이 모두 `\r`로 끝나는지 점검합니다(빈 문자열은 `'' in '+-'`가 참이므로 `l and l[0] in '+-'`로 거릅니다). 자식에게도 같은 검사를 요구합니다.
8. **병합 전 보고합니다.** CI가 없으면 로컬 selftest가 유일한 검증이라고 PR 본문에 적습니다. squash 병합 뒤에는 `state,mergedAt`와 로컬 기본 브랜치 = `origin`을 확인합니다. 리뷰에서 찾아 고친 결함은 PR 본문에 따로 적습니다.
9. **스킬에 반영합니다.** `skill_manage` patch는 배치가 원자적입니다(앵커가 둘 이상 일치하면 전체 롤백이므로 유일한 줄을 앵커로 씁니다). 파일마다 저장소 HEAD와 `sha256`을 대조하고, 어긋나면 `diff`로 위치를 찾습니다(빈 줄 하나도 잡힙니다). `SKILL.md`는 큐레이터가 계속 고치므로 통째로 덮지 말고 줄 단위로 고치며, 새 동작과 어긋난 기존 문장("아직 구현되지 않았다" 류, 대체된 우회 절차)은 그 자리에서 고칩니다. 반영 뒤 스킬 폴더에서 selftest를 직접 돌리고(`PYTHONDONTWRITEBYTECODE=1`, 임시 `RLAB_HOME`) `sync_from_skill.py`로 미러가 일치하는지 확인합니다.
10. **기존 run 원장으로 효과를 볼 때**는 읽기 전용 사본에만 질의하고 끝나면 지웁니다(`references/data-lab.md`). 과거 행의 출처 표기가 덮여 있으면 claim 단위로 보수적으로 분류하고 정의를 함께 적습니다.
